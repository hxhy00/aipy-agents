# AiPy 智能体开发规范速览

## 一、智能体是什么

AiPy 智能体是一个以 MCP 协议对外提供能力的独立程序。它不需要自建界面，只要把工具（Tool）设计好，宿主应用就能自动发现、调用并渲染结果。一个合格的智能体由四部分组成：清单文件 manifest.json、入口服务 server.js、提示词 prompts、以及可选的嵌入式视图。

智能体的核心价值在于「能力封装」：把一段专业流程沉淀成可复用的工具，让非专业用户也能获得专家级的产出。

## 二、开发流程

开发遵循五步：

1. 明确场景：先写清楚用户是谁、在什么场景下用、要产出什么；
2. 设计工具：按最小完备原则拆分工具，每个工具只做一件事，描述写清参数与下一步；
3. 实现服务：入口监听 0.0.0.0 随机端口，长耗时任务下沉后台异步执行；
4. 编写提示词：把方法论写进系统提示，引导模型按流程组合工具；
5. 打包验证：构建产物后用冒烟测试跑通全链路，再打包为 dxt 分发。

## 三、工程约束

几个容易踩坑的地方：

- 端口必须监听 0.0.0.0，由系统随机分配，避免多实例冲突；
- 长耗时任务（如视频渲染）不要在对话轮次内同步等待，应提交任务后返回任务编号，由后续查询接口轮询进度；
- 工具返回值优先使用 Markdown 文本，结构化数据放 structuredContent，方便宿主渲染；
- 依赖安装优先使用国内镜像源，保证企业内网环境可用。

## 四、常见问题

问：为什么智能体的工具要拆得这么细？
答：因为模型是按工具描述来选择下一步动作的。粒度清晰的工具配合提示词里的流程图，能显著降低误调率。

问：渲染类功能超时怎么办？
答：把渲染下沉到独立服务端进程，MCP 工具只负责任务提交与状态查询，两端通过本地 HTTP 通信，互不阻塞。
