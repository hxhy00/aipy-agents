# 图片同步与保留规则

## 1. 图片属于正文

PNG、JPG、JPEG、GIF、SVG、WebP、截图、流程图、表格截图、海报、二维码、Logo、示意图和产品图都属于源内容，必须与文字同等对待。

## 2. 同步要求

1. 先统计源图片总数和出现顺序。
2. 按文档锚点插入 HTML，尽量保持与上下文位置对应。
3. 不遗漏、不调序、不集中移动到文章末尾。
4. 不用图库图、AI 生成图或无关图片替代。
5. 不裁掉二维码、Logo、表格、文字或流程图信息。
6. 不改变原图表达；除非用户明确要求，不重绘、不调色、不加字。

## 3. 不同来源

- Word：读取文档关系与媒体资源，按正文锚点还原。
- Markdown / HTML：解析相对路径、附件路径、网络地址或 data URI；确认实际资源可用。
- TXT：通常没有内嵌图片；只处理用户同时上传的明确配图。
- 公众号链接：在允许访问时读取正文图片；不可访问时说明限制并请用户提供导出文件或截图。
- 截图：若截图本身是正文内容，按原图处理；若只是风格参考，不混入正文。

## 4. 无法提取时

不得静默删除。必须在原位置保留：

`此处插入原文第 X 张图片`

占位符应放入明显的图片容器，并在交付说明中列出缺失图片序号、原位置和需要用户替换的方式。不要编造图片说明。

## 5. 视觉美化

可根据风格使用圆角、白边、细边框、阴影、卡片、满宽、杂志式留白、科技线框或渐变边框。统一同篇图片处理，并始终保留：

`display:block;width:100%;max-width:100%;height:auto;`

原文有图片说明时保留并设计；没有就不新增。二维码保持清晰，不叠加滤镜、渐变或过强阴影。

## 6. 图片核验

检查 HTML 中的真实图片与占位符数量之和是否等于源图片数；再检查顺序、上下文位置和来源。只检查 `<img>` 数量不够。
