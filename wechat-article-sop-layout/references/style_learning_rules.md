# 案例学习与风格融合

## 1. 学习对象

用户可提供公众号链接、截图、历史文章、模板截图或多个参考案例。先判断素材是“正文来源”还是“风格参考”，不要把参考图片误放进正文。

## 2. 提炼设计语言

逐项记录：

- 整体气质和信息密度。
- 背景、主色、强调色与灰阶冷暖。
- 一级、二级、三级标题结构。
- 正文宽度、字号、行高、段距和留白。
- 图片比例、边框、圆角和说明样式。
- 引用、卡片、分割线、ICON 和结尾处理。
- 阅读节奏与每屏视觉焦点。

将观察转写为可执行参数，例如“米白背景 + 朱砂细线 + 直角卡片”，而不是“做得和某账号一样”。

## 3. 禁止复制

不得复制第三方 Logo、插画、专有字体、标志性版式、独特图标或可识别的完整模板。不能生成与参考页面高度相似的结构。

## 4. 单案例原创化

保留 2–3 个抽象原则，至少主动改变以下两项：标题骨架、导航方式、卡片形态、分割线、图片框、留白节奏或强调方式。最终应“气质相通，但明显是新设计”。

## 5. 多案例 Style Fusion

1. 分别提炼每个案例的设计语言。
2. 找出共同点，作为统一基础。
3. 选择一个主导风格，约占 70–80%。
4. 其他案例每个只贡献一个互不冲突的特征。
5. 用新的色值、尺度和组件关系重新组合。

示例：A 提供标题层级，B 提供配色逻辑，C 提供卡片组织，D 提供留白节奏。不要把四个页面切块拼接。

## 6. 冲突处理

冷暖、圆角、线条粗细、阴影强度或字体气质冲突时，服从主导风格。单篇最多保留两种视觉语言，宁可克制，也不做素材拼盘。

## 7. 系列迭代

锁定品牌主色、正文参数、标题家族和落款处理；轮换导航、分割、卡片和图片框组合。记录本篇使用的组件，下篇至少替换两类显著组件，保持系列统一但不重复。
